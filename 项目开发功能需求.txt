# 1. 项目定位

开发一个面向个人及小规模跑团使用的轻量级 Web 工具平台。

核心目标是提供一套可以在浏览器中直接使用的：

* 骰子投掷工具
* 随机表工具
* 词条匹配工具
* 随机内容生成器
* 多表组合生成工具
* 本地数据管理工具

项目强调：

**轻量、实用、功能丰富、本地优先。**

项目第一阶段不需要账号、服务器、数据库或多人实时联机，核心功能全部在浏览器本地运行。

最终通过 GitHub Pages 提供访问。

---

# 2. 功能模块

## 2.1 骰子工具

支持常见骰子：

* d2
* d4
* d6
* d8
* d10
* d12
* d20
* d100

同时允许输入自定义骰子面数。

支持多骰子：

```text
1d20
2d6
3d6
4d6
2d20
```

至少支持：

```text
NdM
NdM+X
NdM-X
```

结果需要显示：

* 每颗骰子的结果
* 基础总值
* 修正值
* 最终结果

后续预留：

* Advantage / Disadvantage
* Keep Highest / Lowest
* 重掷
* 爆骰
* 成功数
* 阈值判定
* 自定义骰子规则

---

# 3. 随机表

建立通用随机表系统。

随机表可以包含：

* 名称
* 描述
* 分类
* 标签
* 结果范围
* 结果文本
* 权重

支持：

* 等概率随机
* 数值范围匹配
* 权重随机
* 分类
* 标签
* 搜索
* 自定义随机表

例如：

```text
城市夜间事件

1-20    平静无事
21-40   遇到陌生行人
41-60   发现可疑踪迹
61-80   遭遇突发事件
81-95   危险出现
96-100  特殊事件
```

---

词条可以用于：

# 5. 骰子与词条匹配

这是平台的核心功能之一。

典型流程：

```text
骰子
 ↓
获得数值
 ↓
匹配随机表
 ↓
得到结果
 ↓
关联词条
 ↓
生成最终内容
```

例如：

```text
1d100 → 73

匹配 61-80

结果：
在街角发现异常踪迹
```

骰子、随机表和词条应当能够互相组合，而不是作为三个完全独立的功能。

# 6. 随机生成器

提供通用的内容生成能力。

预设生成器可以包括：

* NPC
* 地点
* 事件
* 遭遇
* 物品
* 任务
* 环境
* 剧情钩子

例如 NPC：

```text
职业
+
性格
+
外貌
+
动机
+
特殊特征
```

例如事件：

```text
事件类型
+
地点
+
相关人物
+
事件强度
+
特殊情况
```

生成器应该尽量通过数据和配置驱动，而不是为每一种生成内容单独硬编码逻辑。

---

# 7. 组合生成

允许一个生成器包含多个随机步骤。

例如：

```text
夜间城市事件

① 天气
② 地点
③ 遭遇类型
④ NPC
⑤ 事件强度
⑥ 特殊情况
```

一次生成：

```text
天气：小雨
地点：废弃市场
遭遇：陌生人
强度：危险
特殊情况：发现隐藏通道
```

后续允许不同生成步骤之间存在条件和数据关联。

# 8. 搜索与筛选

以下内容需要具备搜索和筛选能力：

* 随机表
* 词条
* 生成器

* 关键词

* 查看

---

# 10. 自定义内容

用户可以创建：

* 自定义随机表
* 自定义词条
* 自定义生成器

内置数据和用户数据需要区分。

内置数据原则上不可被用户直接修改。

---

# 11. 用户体验

项目整体定位为工具，不追求复杂的视觉效果。

重点：

* 操作简单
* 页面响应快
* 信息清晰
* 功能容易找到
* 结果容易复制
* 桌面端优先
* 同时兼容移动端
* 不需要复杂动画

不需要为了游戏感加入大量动画、特效或复杂交互。

---

# 12. 第一阶段 MVP

第一阶段必须完整实现：

```text
首页
骰子工具
骰子表达式
随机表
词条库
骰子→随机表→词条匹配
基础随机生成器
搜索与筛选
历史记录
本地保存
本地读取
JSON 导入
JSON 导出
响应式 UI
```

最重要的业务链路：

```text
骰子
 ↓
结果
 ↓
随机表
 ↓
词条
 ↓
最终生成内容
 ↓
本地保存
 ↓
重新读取
```
