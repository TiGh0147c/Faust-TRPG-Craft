# 1. 数据总体结构

项目数据分为两类：

```text
内置数据
用户数据
```

内置数据随项目发布。

用户数据保存于浏览器本地。

两者不要混为一体。

---

# 2. 随机表数据

随机表至少包含：

```json
{
  "id": "example-table",
  "name": "城市夜间事件",
  "description": "夜间城市随机事件",
  "category": "event",
  "tags": ["城市", "夜晚"],
  "mode": "range",
  "entries": []
}
```

具体字段可以根据实际实现调整。

表项需要支持范围或权重。

---

# 3. 词条数据

词条至少包含：

```json
{
  "id": "example-entry",
  "name": "异常踪迹",
  "content": "在街角发现异常踪迹",
  "category": "event",
  "tags": ["城市", "探索"],
  "weight": 1
}
```

根据需要可以增加：

* 关联词条
* 条件
* 效果
* 变量

---

# 4. 生成器数据

生成器建议采用步骤结构：

```text
Generator
 ├── 基本信息
 ├── Steps
 │    ├── 使用随机表
 │    ├── 结果处理
 │    └── 变量
 └── 最终输出模板
```

例如：

```text
NPC Generator

Step 1 → 职业
Step 2 → 性格
Step 3 → 外貌
Step 4 → 动机
Step 5 → 特殊特征
```

最终通过模板组合结果。

---

# 5. 用户数据

用户数据至少包括：

```text
userTables
userEntries
userGenerators
history
favorites
settings
```

这些数据全部存储在用户本地。

用户不能因为：

* 刷新页面
* 关闭网页
* 重新打开网页

而意外丢失正常保存的数据。

---

# 6. 数据操作

为本地数据提供统一的数据访问层：

```text
create
read
update
delete
```

并提供：

```text
import
export
backup
restore
```

功能。

不要让各个页面直接操作 IndexedDB 或 localStorage。

---

# 7. 数据备份

用户可以将自己的数据导出为 JSON。

例如：

```json
{
  "app": "TRPG Tool",
  "version": 1,
  "exportedAt": "...",
  "data": {
    "tables": [],
    "entries": [],
    "generators": [],
    "favorites": [],
    "settings": []
  }
}
```

导出的文件应当能够在之后重新导入。

---

# 8. 数据导入

导入过程中需要：

```text
选择 JSON 文件
 ↓
解析
 ↓
格式检查
 ↓
版本检查
 ↓
必要的数据迁移
 ↓
写入本地
```

应该明确处理：

* 文件损坏
* JSON 格式错误
* 缺失字段
* 数据版本不兼容
* 重复 ID
* 无效数据类型

不能因为一个错误的导入文件导致现有数据被直接破坏。

必要时应先验证成功，再执行覆盖。

---

# 9. 数据清理

设置中应该提供：

```text
查看本地数据
删除历史记录
删除用户数据
恢复默认数据
清空全部本地数据
```

涉及清空全部数据的操作需要二次确认。

---

# 10. 数据安全与隐私

项目不需要用户账号，因此不收集用户个人信息。

用户创建的数据原则上只保存在本地浏览器。

不要将本地数据自动上传到服务器。

导出文件由用户自己管理。

# 12. GitHub Pages

项目最终使用 GitHub Pages 部署。

推荐使用：

```text
GitHub Actions
```

自动完成：

```text
push main
 ↓
安装依赖
 ↓
构建
 ↓
生成 dist
 ↓
部署 GitHub Pages
```

本地开发完成后只需要：

```text
git add
git commit
git push
```

即可触发部署。

---

# 13. 部署目标

第一阶段目标：

```text
https://USERNAME.github.io/REPOSITORY/
```

如果后续增加自定义域名：

```text
https://CUSTOM-DOMAIN/
```

需要同时调整 Vite 的基础路径配置。

---

# 14. 可靠性要求

项目至少需要保证：

```text
npm install
npm run dev
npm run build
```

都能正常执行。

生产构建不能依赖开发环境文件。

本地数据功能不能因为 GitHub Pages 的静态环境而失效。

导入导出功能需要在生产环境正常工作。

---

# 15. 部署后的核心工作模式

最终用户使用流程：

```text
打开网站
 ↓
读取内置数据
 ↓
读取用户本地数据
 ↓
使用骰子 / 随机表 / 生成器
 ↓
产生结果
 ↓
用户可收藏或保存
 ↓
数据写入本地
 ↓
下一次打开网站继续使用
```

整个流程不需要后端服务器。
